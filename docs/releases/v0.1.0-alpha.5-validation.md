# alpha.5 release preparation — 2026-10-15

The candidate bumps the workspace, standalone extension and both lockfiles to
`0.1.0-alpha.5`. README download links and CHANGELOG point to that version;
historical benchmark/demo provenance keeps the version it actually used.

rollback/catalog/preflight fixes and the five additional demand-shaped demos.

## CI and publication boundary

The source baseline `4849ef4` passed both Linux x86_64 and macOS arm64 CI in
[run 38822666940](https://github.com/SFARL/ivmlite/actions/runs/38822666940).
The previous alpha.4
[release workflow](https://github.com/SFARL/ivmlite/actions/runs/38249049359)
succeeded and published both platform archives plus SHA256SUMS. These are
baseline evidence; candidate CI must separately pass at the preparation PR's
exact head before tagging.

No alpha.5 tag or public release is created during preparation. The tag-triggered
release workflow cannot have alpha.5 results yet. After candidate CI is green
and the release is requested:

1. Tag the reviewed commit `v0.1.0-alpha.5`; confirm both release build jobs and
   the publish job succeed for that tag's SHA.
2. Confirm GitHub marks it a prerelease and uses `v0.1.0-alpha.5.md` as notes.
3. Download **both** platform archives and SHA256SUMS, validate the checksums,
   exact member list and architecture, then load each extracted library on its
   matching host and run the quickstart/refresh/rollback/reopen smoke.
4. Confirm README download links resolve to the published assets. Record the
   release run and downloaded-asset digests; a local candidate digest must not
   be substituted for those GitHub-built artifacts.

M2a's [minimal spec](../superpowers/specs/2026-10-15-m2a-nonuniform-validation-design.md)
is written; implementation and measurements are the next step. Nexmark query
classification and the Turso comparability probe follow that validation.
