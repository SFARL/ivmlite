# ivmlite v0.1.0-alpha.1

This is the first public technical preview of ivmlite, an experimental SQLite
loadable extension for incrementally maintained grouped aggregates.

It maintains `COUNT(*)` and integer `SUM` over `STRICT` tables, with one fixed
predicate and an optional two-table inner equi-join. Writes are captured by
ordinary SQLite triggers; applications explicitly refresh a view when they
want pending changes applied.

The release includes Linux x86_64 and macOS arm64 archives plus `SHA256SUMS`.
Each archive contains the loadable library, README, LICENSE, and changelog.

Start with the [quick start](https://github.com/SFARL/ivmlite#quick-start) and
read the [supported SQL](https://github.com/SFARL/ivmlite#supported-view-sql)
before trying an existing database.

The first case study results are deliberately mixed: Datasette and Taproot
slices cross over in favour of ivmlite for a 250k-row base with 100 inserted
rows, while the Org-roam join/count slice remains slower than direct SQLite.
See the repository's evaluation document for methodology, exact timings and
adaptation gaps.

This is an alpha. The supported SQL and persisted shadow-table format may
change without migration. Please report real schemas and queries, including
ones that ivmlite rejects or makes slower.
