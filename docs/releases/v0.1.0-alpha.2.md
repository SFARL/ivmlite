# ivmlite v0.1.0-alpha.2

The second technical preview of ivmlite, an experimental SQLite loadable
extension for incrementally maintained grouped aggregates. It is the first
release measured against hand-written triggers and full recomputation.

**Breaking: the shadow-table format is now 3.** Views created with
`v0.1.0-alpha.1` report a format error on every read and refresh. They still
open as broken views, so `DROP TABLE <view>` works with this release loaded;
drop every alpha.1 view, then create them again. The supported SQL is
unchanged.

## What changed

- **Retractions are index searches.** Each view's output table gets an index
  over its output columns. Before, every retracted output row scanned the
  whole output table; at 100,000 groups that turned a 0.13 s refresh into
  17.6 s.
- **Cheaper writes with many views.** The REPLACE-capture check reads
  `sqlite_schema` once per written row instead of four times: about 1.4–1.5x
  less write cost at 200 views than in alpha.1. Databases stay readable and
  writable by SQLite versions older than 3.44.

## What the benchmark found

The full results, data and reproduce commands are in
[docs/bench/README.md](https://github.com/SFARL/ivmlite/blob/v0.1.0-alpha.2/docs/bench/README.md).
In short:

- ivmlite beats full recomputation by more than 2x in 55 of the 68 measured
  configurations, and by 17–909x at one million base rows;
- it loses in the small-table corner (10,000 rows), especially with large
  batches;
- on total write + refresh time it stays 4–15x slower than special-purpose
  hand-written triggers in most confirmed configurations;
- its write cost grows with the number of views, to about 60–70 µs extra per
  written row at 200 views, yet from 50 views up it is lower than maintaining
  that many hand-written summary tables.

These numbers come from in-memory databases with uniformly distributed data
and one refresh per batch. Real workloads will differ; reports of real schemas
and queries, including ones ivmlite rejects or makes slower, are the most
useful feedback.
